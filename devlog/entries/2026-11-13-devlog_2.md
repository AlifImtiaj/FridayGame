# Devlog #02 — Texture Management & Level System

## What I worked on

Today, I worked on improving how textures are handled in Friday Engine. I wanted to separate the texture loading part from the rendering part instead of keeping everything inside the `Image` class.

While working on this, I also spent quite some time thinking about how resources should be created and passed to the objects that need them. I ended up making a `LevelManager` and a base `Level` class to organize the level system.

Figuring out how all these classes should work together took me some time. I had to think about which class should be responsible for what and how to keep them in a one-way dependency structure.

## What I implemented

**Texture2D**

I created a new `Texture2D` class to handle texture resources. Its job is to load an image and store the resulting SDL texture.

The main reason I did this was to avoid creating the same texture multiple times for different objects. For example, if multiple `SpriteRenderer` objects need to render the same image, they can share one `Texture2D` instead of each creating their own texture.

This should help reduce unnecessary VRAM usage when multiple objects use the same texture.

I also added error handling to the texture loading process. `CreateTextureFromPath()` now returns a bool to indicate whether loading was successful, and it logs an error if something goes wrong.

I improved the cleanup process as well so that the old texture gets destroyed when loading a new one.

**SpriteRenderer**

I renamed the old `Image` class to `SpriteRenderer`. I thought the new name made its purpose much clearer.

I also separated texture management from rendering. `SpriteRenderer` no longer owns the actual SDL texture. Instead, it holds a pointer to a `Texture2D` object and uses its texture when rendering.

This way, the same texture can be shared by multiple renderers and `SpriteRenderer` can focus on what it is supposed to do, rendering the sprite.

I also added some null checks before rendering, so it doesn't try to render if the renderer or texture is unavailable.

**LevelManager & Level**

I created a `LevelManager` and a base `Level` class to organize how levels are handled.

The idea is that LevelManager manages the levels, while individual level classes handle their own setup, updates, and rendering.

I also decided that resource loading and assignment should be handled during level setup. For example, a level can create a `Texture2D`, load the required image, and then pass that texture to the appropriate `SpriteRenderer`.

This keeps `Texture2D` independent of the rest of the engine. It doesn't need to know whether a `Player`, a `Level`, or any other object exists. It just manages its texture.

## Problems I ran into

**Segmentation Fault When Getting the SpriteRenderer**

While connecting Player with `SpriteRenderer`, I ran into a segmentation fault when trying to access any of the function that accesses the `Texture2D` pointer stored inside `SpriteRenderer`.

It happened because I wrote the function to return SpriteRenderer by value instead of returning a reference. And not gonna lie, it took my some time to figure out that this was causing the Segmentation Fault.

```cpp
SpriteRenderer GetSprite();
```

**Figuring Out Resource Management**

Another challenge was deciding where textures should be created and how they should reach the objects that need them.

I didn't want every `SpriteRenderer` to create its own texture, and I also didn't want `Texture2D` to depend on classes like `Player` or `Level`.

It took me some time to figure out how to connect everything without mixing their responsibilities together.

## How I solved them

**Returning a Reference to SpriteRenderer**

I changed `GetSprite()` to return `SpriteRenderer&` instead of returning `SpriteRenderer` by value.

This allows me to access the actual `SpriteRenderer` object owned by `Player`, instead of working with a copy of it.

```cpp
SpriteRenderer& GetSprite();
```

**Separating Texture Loading and Rendering**

I moved texture management into `Texture2D` and kept rendering responsibilities inside `SpriteRenderer`.

Now, `Texture2D` owns the SDL texture, while `SpriteRenderer` only references the texture it needs to render. This makes it possible for multiple renderers to share the same texture.

I also moved the responsibility of acquiring and assigning resources to the level setup. The level creates the required texture, loads it, and assigns it to the appropriate renderer.
